# Модуль с задачами

Текущая версия протокола синхронизации — 1. Сетевые модели и мапперы находятся
в `api/v1`.
`SyncRepository` создаёт UUID `syncId` один раз на одну синхронизацию и отправляет
его вместе с `syncProtocolVersion` в `/sync/start` и `/sync/finish`.

Если сервер возвращает `426 APP_UPDATE_REQUIRED`, фоновая задача сохраняет
состояние предупреждения в SharedPreferences и завершается без повторов.
Основное приложение должно вызвать `SyncUpdateRequiredDialog()` в корневом
Compose-контенте (рядом с `AppNavigation`), чтобы предупреждение показывалось
поверх любого раздела. Сам `SyncRepository.sync()` также нужно оборачивать
обработчиком `SyncApiException` и записывать `APP_UPDATE_REQUIRED` через
`SyncUpdateRequiredStore.record(...)`: этот прямой вызов не проходит через
обработчик WorkManager. Закрытие диалога запоминается для текущей версии
приложения и того же минимума протокола. Состояние автоматически очищается,
когда меняется Android `versionCode`; поэтому при публикации обновления
`versionCode` должен быть увеличен.


## Расписание и локальная база

В `Note` расписание хранится только в отдельных полях (`addedDates`,
`cancelledDates`, `patterDates`, `patternType`, `dateSince`, `dateTill`).
Календарь по умолчанию показывает виртуальные вхождения шаблона, вычисленные по
расписанию. `NoteDateEntry` создаётся только после действия пользователя:
изменения карточки для даты, отметки о выполнении или удаления карточки для этой
даты. Такая запись целиком заменяет шаблон для своей даты; tombstone скрывает
вхождение шаблона. Статус, заголовок, описание и стиль хранятся в снимке. Список,
теги и награда берутся из связанного `Note`.

Room сейчас использует версию схемы 1. Переходных миграций нет: перед запуском
этой версии удалите старую локальную базу. В синхронизации датированные записи
передаются в JSON-поле `noteDateEntries`; локальная модель и таблица называются
`NoteDateEntry` и `note_date_entries`.

Карточка хранит подписи расписания, списка и тегов в отдельных полях
`scheduleLabel`, `listLabel`, `tagsLabel`. Действия по нажатию передаются через
`CardAction`, без строковых ключей.
